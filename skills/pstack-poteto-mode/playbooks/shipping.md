### Shipping

Prepare a verified local handoff. Independently verify each item and hand off only the contiguous verified run from the root. This suite never commits or pushes, including through forge, stack, or shipping wrappers. Do not merge, retarget, arm auto-merge, post verdict comments, or update remote state under the local grant. External publishing requires separate specific authorization and cannot lift the no-commit/no-push restriction.

1. **Identify the artifact and prerequisites.** Record the root baseline, dependency order, item boundaries, and existing PR heads when available. For dirty local work, capture changed paths and content digests, including relevant untracked files. A head SHA alone does not identify uncommitted work. Inspect scripts before use. Missing tools, credentials, or services block their dependent checks.

   Independent items require a stable isolated artifact containing the recorded baseline plus only that item. Disjoint writers in a dirty checkout do not isolate build inputs. Record dependency state, check configuration, and every relevant input. If isolation cannot preserve pending work safely, serialize preparation and verification using stable retained artifacts. Do not implicitly stash, reset, delete, or commit for isolation. If no safe artifact is available, return `BLOCKED`. Only Autopilot-stack may verify combined dependent artifacts, with each parent identified.

   Forge status is optional evidence for existing PRs, not a prerequisite to local-only work. Use only authorized read operations. Before a GitHub watcher read, follow the dependency and authentication prerequisites in `playbooks/babysit.md`. Its `--status-only` mode still makes authenticated reads. Use a bounded status pass, not its driving, queued-landing, mutation, or unbounded watch flow. This playbook does not authorize any writes or slash-command loops suggested by linked legacy material.
2. **Verify each item independently.** Only the primary dispatches execution runners and reviewers. Enforce a hard aggregate maximum of two active children across all owners, runners, comment reviewers, and artifact reviewers, without configuration or pilot exceptions. Count retained resources and uncertain acquisitions until reconciled. Select exact approved task models through pstack-runtime and report missing model diversity honestly. No runner or reviewer may have authored or fixed the item, publish a verdict, or delegate.

   After the candidate exists, the primary commissions pstack-no-comments critique through a read-only reviewer within the cap. Owners never run its spawning step. Return accepted fixes to the scoped owner and refresh the artifact and affected checks before acceptance.

   Dispatch a nonauthor `poteto-agent` runner with the appropriate policy task, normally `implementation`, for named permitted checks. Freeze source inputs throughout execution and review. Allow only scoped generated outputs, not source fixes. The runner compares parent against the exact proposed item and runs it as a user would. Use permitted Playwright for web interaction, an owned PTY for interactive CLIs, or the installed IDE or mobile driver. Record the runner's identity and explicit nonauthor evidence. If no capable permitted nonauthor runner is available, required execution is `BLOCKED`.

   Then dispatch a `poteto-reviewer` with the review task model to inspect the actual artifact, diff, and execution receipts. The role's policy permits read tools and limited Git inspection, not general shell, Playwright, or PTY execution. Code Mode cannot bypass those restrictions. Tool availability is not permission. Review is `BLOCKED` if the actual artifact is inaccessible through permitted reads. A manifest alone is not the diff. Retain commands, output, before-and-after input identities, runtime inputs, and reviewer identity in the local report. Return `PASS`, `PASS+NOTES`, `FAIL`, or `BLOCKED` there, never as a remote comment. Missing required IDE, mobile, or cloud drivers stop the lane as `BLOCKED`. Required hosted Bugbot remains a dependent-service blocker without that service. Local read-only review is not hosted or cloud parity. CI green and author self-reports are not independent verdicts.
3. **Find the contiguous verified run.** Start at the lowest dependent item and stop at the first missing, failed, or blocked required verdict. Items below it form the handoff run. The highest verified item is the ceiling. A passing item above a gap waits. An independent item can be handed off separately only after fresh verification against its independent baseline.
4. **Recheck evidence against current content.** Compare recorded refs and local content digests with the actual artifact immediately before handoff. A changed parent, patch, dependency, check configuration, or runtime environment requires affected checks and independent lanes to run again. A new head needs its own checks. Never carry a dirty-checkout verdict using SHA equality alone.

   For committed artifacts already present, compare `git patch-id` between the recorded parent/head pair and the current parent/head pair as one drift signal. Patch equality alone does not prove integration behavior. If base changes can affect callers, dependencies, build output, or checks, rerun against the updated-baseline-plus-only-item artifact, or the explicit ancestor chain under Autopilot-stack. Reuse an unaffected lane only with recorded evidence that its inputs and behavior are unchanged. A lane without comparable build output must be rerun when its runtime inputs drift. Record noise only when the same difference occurs across repeated builds of the same artifact. Never call an unrun lane passed.
5. **Deliver locally, without landing.** Freeze the verified artifacts and provide the ordered run, ceiling, local report paths, and remaining gaps. Do not execute commit, push, merge, auto-merge, retarget, comment-update, or remote-status-update wrappers. If integration or publication requires forbidden operations, report the gap and stop that operation. Keep any proposed external actions as an unexecuted operator plan. Do not suggest that separate publish authorization overrides the host's absolute no-commit/no-push rule.
6. **Stop at the ceiling.** Extending the run or changing its content requires a new verification pass. If observation after handoff is requested, use approved bounded `pstack.loop` scheduling with a stop predicate, `intervalSeconds`, `maxRuns`, and `durationSeconds`. It needs explicit approval and an active server. Cancel on completion or stop. Do not create nested schedules, another polling loop, or an automatic ownership transfer after restart. Worker ownership recovery/transfer is not implemented.

**Reply.** State the local run and ceiling, exact artifacts, each verdict and its independent verifier, tool-evidence paths, and the next gap. Separate static checks from executed behavior. State that nothing was committed, pushed, merged, retargeted, or externally published. Missing-service records are blockers, not proof of full parity.
