### Autopilot-stack

Prepare one dependency-ordered local stack for the operator to review. Follow Autopilot-full's implementation, independent verification, schedule, and permission rules. Its hard aggregate maximum of two active children includes every owner, runner, comment reviewer, and artifact reviewer. Configuration and pilots cannot raise it. This playbook changes the preparation shape, not the host's publishing limits.

1. **Prepare dependent items.** Owners report STACK-READY local artifacts instead of independent-item readiness. Record each item's intended parent and exact input artifact. A dependent item starts only after its parent's output is available in an authorized local checkout. Container workers cannot see an uncommitted parent patch. Serialize dependent edits when necessary and retain a stable combined artifact for each link's verification. Freeze its source inputs while the nonauthor runner executes and the reviewer reads receipts. Preserve pending dirty work without implicit stash, reset, deletion, or commit. If safe preparation is unavailable, mark the link `BLOCKED`. Do not commit or push to bridge that gap.
2. **Keep one topology owner.** The primary records the linear order, parent identities, changed paths, and local content digests. Only the primary dispatches integration work, with one scoped writer. Children never delegate, rebase, retarget, merge, close PRs, or arm auto-merge. No owner publishes its branch. Treat a proposed PR base chain as a local plan, not an existing forge stack.
3. **Reconcile drift bottom-up.** Apply Autopilot-full step 5 to the root's baseline. Each descendant instead includes only its recorded ancestors plus that item, never an unrelated sibling. Reverify every affected descendant after a parent changes. Use Shipping's identity checks against the actual combined artifact. If a chain rewrite needs forbidden operations, stop and report the blocker rather than running a stack wrapper.
4. **Deliver the verified local chain.** Provide order, parent identities, changed files, independent verdicts, and actual verification receipts for every link. Shipping defines the contiguous verified run and its ceiling. A verified upper link waits when a lower link is blocked. Freeze accepted artifacts at handoff. Any later edit invalidates affected evidence and needs a new authorized pass.

Choose Autopilot-full for independent items prepared separately against trunk. Choose Autopilot-stack for dependent or coupled changes delivered in one ordered local chain. Neither choice grants landing authority. External PR creation, base edits, comments, or merges need separate specific authorization. This suite still never commits or pushes, even through wrappers.

**Reply.** Give the local stack root and tip, dependency order, a verdict and evidence pointer for each link, the handoff ceiling, parked items, and blockers. Include PR links only for existing PRs actually read or supplied. State what remains local and unexecuted.
