### Autopilot-full

Prepare a queue of independent changes through implementation, independent local verification, and verified local handoff. One owner carries each item through fixes and proof. The primary owns dispatch and acceptance, not the owner's files.

Full retains independent delivery intent. Each item starts from the recorded trunk baseline and must stand alone. Autopilot-stack instead prepares dependent work in one ordered chain. Neither mode commits, pushes, opens or merges PRs, posts comments, or updates trackers under the local grant. External publishing needs separate specific authorization. It cannot override this suite's absolute no-commit/no-push rule, including wrappers.

1. **Record the queue and gates.** Scope the grant to named items and local paths. Record dependencies, dirty files to preserve, the stop predicate, and required services. Read the current project-local mode and `pstack-models.json`. Do not treat a request for a plan as authorization to execute it.
2. **Dispatch one bounded owner per item.** Only the primary dispatches native children or runtime workers under pstack-runtime. Enforce a hard aggregate maximum of two active children across all owners, runners, comment reviewers, and artifact reviewers. Configuration and pilots never raise it. Count retained resources and uncertain acquisitions until reconciled, not just active model turns. Children cannot delegate. Native children may own disjoint paths in the dirty checkout, but this does not isolate build inputs. Container workers require a committed ref, exclude parent uncommitted changes, and execute offline. Explicit local workers lack process isolation. Neither is a cloud equivalent. A cloud-required item remains blocked without an actual provisioned, authorized backend.

   Give each owner the mode SKILL.md path, consolidated brief, exact approved task model, allowed files, acceptance checks, timebox, and no-delegation/no-publish restrictions. Keep a local decision trail through pstack-show-me-your-work. Record worker IDs or native child results, artifact locations, and runtime evidence. Keep artifacts local instead of pushing for durability. Worker ownership transfer is not implemented.
3. **Prepare independent items, never an implicit stack.** Each item needs a stable isolated verification artifact containing the recorded trunk baseline plus only that item. Record all build inputs, relevant untracked files, dependency state, and check configuration. Preserve pending dirty work in place. Disjoint writers in one checkout do not meet this requirement. If parallel isolation is unsafe, serialize preparation and verification using stable retained artifacts. Do not implicitly stash, reset, delete, or commit for isolation. If no safe preparation is possible, mark the item `BLOCKED`.

   Owners implement, self-check, and run pstack-unslop. Record changed paths, base ref, head SHA where available, and uncommitted content digests. Do not create commits to obtain an identity. After the candidate exists, the primary commissions the pstack-no-comments reviewer within the same two-child cap. The owner never runs its child-spawning step. The primary returns accepted findings to the scoped owner and captures the revised artifact before code-ready acceptance. Run bounded checks and report actual output. Missing tools are blockers, not successful checks.

4. **Independently verify the finished artifact.** The primary dispatches a nonauthor `poteto-agent` runner for permitted runtime checks, then an independent read-only `poteto-reviewer` for artifact and receipt review. Both count against the hard aggregate cap of two. Choose the runner's exact policy task model, normally `implementation`, and the review task model for critique. Record identities and explicit evidence that neither authored or fixed the item. The runner may write only named generated outputs, not source fixes. Freeze source inputs during execution and review. If no capable permitted nonauthor runner is available, mark required execution `BLOCKED`.

   The runner proves load-bearing behavior on the real user-facing app through permitted Playwright, owned PTY, or installed IDE or mobile drivers. The reviewer reads the actual artifact, diff, and receipts. `agents/poteto-reviewer.md` in the bundle root denies general shell and PTY use and limits Code Mode to history. Do not assign Playwright or runtime commands to that role or widen its permissions. Tool availability is not permission. If actual artifact access through permitted reads is unavailable, review is `BLOCKED`. A manifest alone is not the diff. Each verdict names the exact artifact and includes before-and-after input identities, commands, output, and tool evidence. Start multi-model coverage with distinct configured implementation and review model IDs. Report diversity gaps without substituting unapproved models.

   Stop a required lane if its driver is missing. Local review does not replace hosted Bugbot or mandatory cloud verification. Keep those requirements blocked until their actual services are available and authorized. Green CI, a bot approval, and an author's self-proof do not establish an independent live verdict.

   Run the full planned verification once on code-ready content and again for major behavior or design changes. A minor fix still needs fresh independent verification of affected behavior. Batch proven findings back to the sole owner. The primary dispatches a fresh bounded fix child when needed. Silence is not quiescence. Do not replace a stuck writer until actual evidence reconciles execution, writer ownership, retained resources, and capacity. Never let overlapping replacements write one scope.
5. **Reconcile baseline drift before handoff.** Apply Shipping's artifact-identity rules. If trunk changes code the item calls, its callers, dependencies, or checks, prepare and verify a new isolated artifact containing the updated baseline plus only that item. Do not include sibling queue items. Dependent combined artifacts require Autopilot-stack. Scope any integration edits to one writer, then rerun affected independent lanes. If preparation requires a forbidden commit, push, destructive rewrite, or loss of pending work, stop and report the integration gap. Do not claim the item was tested on a base it never ran against.
6. **Audit from the primary.** Changes that loosen acceptance gates need independent evidence and an explicit primary decision. A local countersign cannot bypass operator gates or forge approvals. Retain existing CI and review results only with their real heads and coverage. Do not disable checks to obtain a pass.

   Schedule audits only with explicit approval through `pstack.loop`. Supply a precise stop predicate, `intervalSeconds`, `maxRuns`, and `durationSeconds`. On each wake, reread the current project-local playbook and standing orders, inspect owned-worker status and actual receipts, and record drift or blockers. There is no slash-command loop or unbounded watchdog. The OpenCode server must remain active. An uncertain dispatch pauses for inspection. Cancel when the predicate is met, the budget expires, or the operator stops the run. A schedule never grants external-write authority.
7. **Hand off and stand down.** Follow Shipping for each independent item's local acceptance. Report prepared and blocked items separately. On stop, halt new dispatch, cancel schedules, issue zero-write holds, and record active children and retained artifacts. After restart, do not assume workers died or ownership transferred. Use authorized owner evidence and stop dependent work if access is unavailable.

**Reply.** Report each item's local state, exact artifact, independent verdict and receipts, baseline-drift checks, gate decisions, trail path, and external blockers. State that nothing was committed, pushed, merged, or published. Do not call documentation changes or missing-service records full parity.
