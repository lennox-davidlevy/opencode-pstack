### Worktree and simulator cleanup

1. Inventory without changing state. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <local-base-ref>] [repo-path]`. This requires Bash, Python 3, and Git. It reads only local Git state, never fetches, queries a forge, or reads chat files. Without `-b`, it tries existing `origin/HEAD`, `origin/main`, and `origin/master` refs. Missing defaults leave ancestry unknown. An explicit missing base is an error, not a reason to fetch.
2. Read the table as evidence, not permission. It includes the main worktree and retains the original columns. `SIZE` is not measured and rows follow Git's order. `AGE` is commit age, not last use. `MERGED` is local ancestry only, not squash-merge or current remote evidence. `REMOTE`, `PR`, and `LAST_CHAT` are unknown. `DIRTY` reports tracked WIP, untracked files, and ignored entries separately. Inspection failures remain unknown. Control-character paths are JSON quoted for display, not shell commands. Every row is `review-required`, even clean, merged rows.
3. Check ownership and live activity. Use the runtime's scoped `pstack.history_list` and `pstack.history_read` as historical evidence, then check current live sessions and ask the owner about pinned or paused work. History alone cannot establish inactivity. Have the owning primary check `pstack.worker` status for runtime-owned workers. Container workers use standalone clones that do not appear in `git worktree list`; this inventory is not exhaustive. Unknown activity or unavailable owner status always requires review. Never infer safe inactivity from age, missing history, or an absent worktree row.
4. Obtain exact, specific approval before any deletion. Present each exact path, ownership, current activity evidence, Git state, and the files that would be lost. Tracked edits, untracked files, and ignored artifacts are never disposable by default. Clean or merged state does not authorize removal. Resolve active sessions and workers with their owner; stopping them also requires authorization. If loss or ownership is uncertain, hold the path for review.
5. Recheck immediately before an approved action. Re-read Git state and live session/owning worker status. Changed or unknown evidence pauses the action. Use the owning runtime's lifecycle for its workers, not manual directory removal. For separately approved ordinary Git worktrees, use normal non-forced removal only. A refusal is a reason to stop and review, never to force removal or recursively delete leftovers. Do not automatically prune metadata or delete branches.
6. Treat other storage separately. Simulator devices, runtimes, build artifacts, and package caches need their own inventory and exact approval. A worktree cleanup request is not permission to delete them. After approved actions, re-list local worktrees and record `df -h /`; report only observed changes.

**Reply.** List inventoried paths, approved actions actually performed, paths held for review and why, and coverage gaps including standalone worker clones. Report space reclaimed only when measured before and after. This playbook grants no deletion authority.
